# 把阅读记录做成一份可复现的档案

## 问题

微信读书有阅读统计，但没有好用的个人检索。年度报告是图片，划线散落在 App 里，想法只能一条条翻。同步到 Obsidian 之后，数据变成了本地 Markdown，却仍然只是「文件」：缺少聚合、对比和对外展示的形态。

我想做的不是又一个「读书打卡页」，而是一份能回答四个问题的档案：

1. 时间到底花在哪里？
2. 哪些书真的读完了，哪些只是翻过？
3. 我划过的句子落在哪些书、哪些章节、哪些年月？
4. 我写下过哪些判断，它们对应哪段原文？

## 约束

- **数据源不可控**：笔记由 obsidian-weread-plugin 生成，格式随插件变化；只能读 Markdown，不能要求 API。
- **隐私是硬约束**：同步插件的 `data.json` 里有微信读书登录 Cookie，必须完全不碰。
- **版权是有意识的取舍**：摘录包含书籍原文。第一版只公开 24 条原创想法，第二版扩到全部 60 条批注，第三版公开全部 720 条短摘录并逐条附上批注；靠「短片段、可删除、不拼整章、不提供全文」控制风险，页面明确版权归原作者。
- **部署要便宜**：GitHub Pages 静态托管，无服务器、无数据库。
- **可复核**：页面上每个数字都要能由仓库脚本重新算出来。

## 数据模型

四层，彼此独立：

1. **Book**：书名、作者、进度、阅读时长、最近阅读日期、状态、章节聚合、源划线与去重后摘录计数。
2. **Excerpt**：唯一 id、所属书与章节、日期、原文、可选批注、quoteHash 与字符数。
3. **Thought**：只含有原创批注的子集，保留稳定 id 与所属摘录。
4. **Stats**：官方 lifetime、历年分钟数、逐月分钟数。

想法 id 用 `sha1(bookId + "|" + 去空白文本).slice(0, 12)`，同一句话在不同章节重复出现时只保留第一次。摘录按「空白规范化后的原文」去重：源文件 724 个划线块收敛为 720 条（深度学习 2 条、传播学 1 条、国富论 1 条重复）。另有 1 条只有 `# 读书笔记`、没有划线块的独立想法，用 note-only 条目接住，最终仍是 60 条批注。

## 实现

### 解析

- 按 `# 高亮划线` / `# 读书笔记` 切分区域。
- 划线块以 `> 📌` 开头，向下读取 `💭` 与 `⏱`，止于空行、标题或下一个划线块。
- `### 划线评论` 是读书笔记区的固定小标题，不作为章节名，否则所有批注会挂到一个无意义的章节下。
- 阅读状态是启发式：`readingStatus == 4` 或进度 100% 为读完；180 天内有记录为在读；否则搁置。

第一版有两个解析 bug，都是真实数据暴露出来的：

1. **标题被吞**：块与下一个标题之间没有空行时，原循环会一直读到下一个空行，把标题当成块内容。修复方式是遇到 `^#{2,3} ` 或下一个 `> 📌` 立即停止，并把索引回退一格。
2. **连续划线被合并**：读书笔记区的划线块之间没有空行，原逻辑只保留第一条。修复方式同上，块边界不再只依赖空行。

另一个隐蔽问题是中文路径：`new URL(import.meta.url).pathname` 会把空格和中文百分号编码，导致数据写到错误目录。改用 `fileURLToPath` 之后解决。

### 生成

`build.mjs` 读取笔记目录与统计文件，输出 `books`、`excerpts`、`thoughts`、`stats` 与 `meta` 五个 JSON，再交给 `render.mjs` 拼接 HTML。渲染层没有模板引擎，只有转义函数与字符串数组；页面不引用任何外部资源。

720 张摘录卡一次性 server-render 进 HTML，首屏以外的卡片带 `hidden`；前端 `app.js` 负责时间线/按书双视图、月份与章节筛选、以及每页 20 条的分页。视图状态写进 query（`view/book/month/chapter/page`），刷新和分享都能落回同一屏。

### 校验

- `node --test`：7 组解析与统计断言，覆盖章节归属、连续块、想法去重、note-only 条目、状态判定和统计格式。
- `npm run check`：扫描产物中的手机号、邮箱、身份证、Cookie 关键词、本机路径和第三方脚本；同时校验每条摘录的原文长度、书名与章节非空、quoteHash/quoteLength 一致，以及 meta 计数与 JSON 实际条数一致。

## 设计决策

**从「只公开批注」改成「公开摘录 + 批注」。** 第一版担心版权，只放 24 条想法；第二版扩到全部 60 条批注和对应原文片段。但阅读页真正想回看的是「我当时划了什么、又在旁边写了什么」，所以第三版把 720 条摘录全部公开，让没有批注的划线也能被检索；版权风险通过短片段、可删除、不拼整章来控制，而不是靠隐藏内容。

**官方口径与本地口径分开写。** 官方 lifetime 是 46 小时 43 分、32 本、16 本、501 条笔记；本地同步只有 9 本书、源文件 724 个划线块、去重后 720 条摘录、60 条批注、34 小时 48 分。两者不相加，页面上分别标注。

**两个入口，而不是两个页面。** 时间线回答「我什么时候读了什么」，按书回答「这本书我划了哪些章节」。共用一个卡片池和分页器，切换视图只改排序与筛选，不重新请求数据。

**每页 20 条，前端分页。** 720 条一次性渲染，换取零后端和即时的筛选/翻页；首屏只显示 20 条，避免一次铺满整页。页码越界会自动回收到最后一页。

**全量公开，白名单只作为可选项。** 作品集要展示判断链，而不是挑选过的样本。构建脚本仍保留 `config/curation.json` 白名单能力，想收窄时再加回来；默认关闭，避免新增内容被静默漏掉。

**编辑式排版。** 米色纸感、宋体标题、朱砂强调、大号数字与细分隔线，参考中文书籍与独立杂志，而不是仪表盘。信息层级靠字号、留白与分隔线，不靠卡片阴影。

**零依赖、零请求。** 没有框架、没有字体 CDN、没有分析脚本。页面加载即完整，离线也能看。

## 结果

- 9 本同步书籍，源文件 724 个划线块，去重后 720 条摘录，60 条批注全部公开。
- 页面包含总览图表、书架卡片、时间线/按书双视图摘录区与方法说明；每页 20 条，支持按书、月份、章节筛选。
- 桌面两列、390px 窄屏单列，均无横向溢出；构建、测试、隐私检查、Pages 部署串成一条可重复的流程。
- 构建耗时不到一秒，产物约 300 KB（含 720 条摘录的 HTML、CSS 与 JS）。

## 复盘

- **先做数据，再做视觉。** 如果把页面当起点，很容易先堆组件，最后发现口径和边界都没想清楚。先让 JSON 可信，页面只是投影。
- **真实数据是测试用例。** 两个解析 bug 都不是构造样例能发现的：它们来自「标题没有空行」「连续划线没有空行」这种真实排版。
- **隐私检查要可执行。** 写在文档里的规则容易被忽略；把检查做成 `npm run check`，每次构建都能拦住。
- **公开范围是产品决策，不是技术默认值。** 第一版只放 24 条，第二版全量 60 条批注，第三版再扩到 720 条摘录；每次扩大范围都要同时更新版权说明、校验与删除路径。
