# 把阅读记录做成一份可复现的档案

## 问题

微信读书有阅读统计，但没有好用的个人检索。年度报告是图片，划线散落在 App 里，想法只能一条条翻。同步到 Obsidian 之后，数据变成了本地 Markdown，却仍然只是「文件」：缺少聚合、对比和对外展示的形态。

我想做的不是又一个「读书打卡页」，而是一份能回答三个问题的档案：

1. 时间到底花在哪里？
2. 哪些书真的读完了，哪些只是翻过？
3. 我写下过哪些判断，它们出现在哪本书、哪一章？

## 约束

- **数据源不可控**：笔记由 obsidian-weread-plugin 生成，格式随插件变化；只能读 Markdown，不能要求 API。
- **隐私是硬约束**：同步插件的 `data.json` 里有微信读书登录 Cookie，必须完全不碰。
- **版权是硬约束**：划线包含书籍原文，公开展示会有侵权风险；只能公开自己的批注与元数据。
- **部署要便宜**：GitHub Pages 静态托管，无服务器、无数据库。
- **可复核**：页面上每个数字都要能由仓库脚本重新算出来。

## 数据模型

三层，彼此独立：

1. **Book**：书名、作者、进度、阅读时长、最近阅读日期、状态、章节聚合、划线与想法计数。
2. **Thought**：唯一 id、所属书与章节、日期、文本、引用哈希与长度。原文不进入模型。
3. **Stats**：官方 lifetime、历年分钟数、逐月分钟数。

想法 id 用 `sha1(bookId + "|" + 去空白文本).slice(0, 12)`，同一句话在不同章节重复出现时只保留第一次。引用用 `sha1` 前 12 位与字符数代替，既能校验解析完整性，又不泄漏内容。

## 实现

### 解析

- 按 `# 高亮划线` / `# 读书笔记` 切分区域。
- 划线块以 `> 📌` 开头，向下读取 `💭` 与 `⏱`，止于空行、标题或下一个划线块。
- `### 划线评论` 是读书笔记区的固定小标题，不作为章节名，否则所有批注会挂到一个无意义的章节下。
- 阅读状态是启发式：`readingStatus == 4` 或进度 100% 为读完；180 天内有记录为在读；否则搁置。

第一版有两个解析 bug，都是真实数据暴露出来的：

1. **标题被吞**：块与下一个标题之间没有空行时，原循环会一直读到下一个空行，把标题当成块内容。修复方式是遇到 `^#{2,3} ` 或下一个 `> 📌` 立即停止，并把索引回退一格。
2. **连续划线被合并**：读书笔记区的划线块之间没有空行，原逻辑只保留第一条。修复方式同上，块边界不再只依赖空行。

另一个隐蔽问题是中文路径：`new URL(import.meta.url).pathname` 会把空格和中文百分号编码，导致数据写到错误目录。改用 `fileURLToPath` 之后解决。

### 生成

`build.mjs` 读取笔记目录与统计文件，输出四个 JSON，再交给 `render.mjs` 拼接 HTML。渲染层没有模板引擎，只有转义函数与字符串数组；页面不引用任何外部资源。

### 校验

- `node --test`：7 组解析与统计断言，覆盖章节归属、连续块、去重、状态判定和统计格式。
- `npm run check`：扫描产物中的手机号、邮箱、身份证、Cookie 关键词、本机路径和第三方脚本；断言公开想法没有 `quote` 字段。

## 设计决策

**只公开想法，不公开划线。** 这是版权与隐私的交集。划线数量作为统计保留，原文连哈希之外的任何痕迹都不进公开数据。

**官方口径与本地口径分开写。** 官方 lifetime 是 46 小时 43 分、32 本、16 本、501 条笔记；本地同步只有 9 本书、724 条划线、60 条想法、34 小时 48 分。两者不相加，页面上分别标注。

**全量公开，白名单只作为可选项。** 第一版用 `config/curation.json` 的白名单挑了 24 条，后来决定把 60 条全部公开：作品集要展示判断链，而不是挑选过的样本。构建脚本仍保留白名单能力，想收窄时再加回来；默认关闭，避免新增想法被静默漏掉。

**编辑式排版。** 米色纸感、宋体标题、朱砂强调、大号数字与细分隔线，参考中文书籍与独立杂志，而不是仪表盘。信息层级靠字号、留白与分隔线，不靠卡片阴影。

**零依赖、零请求。** 没有框架、没有字体 CDN、没有分析脚本。页面加载即完整，离线也能看。

## 结果

- 9 本同步书籍，724 条划线，60 条想法全部公开。
- 页面包含总览图表、书架卡片、可筛选批注墙与方法说明，桌面与 390px 窄屏均可用。
- 构建、测试、隐私检查、Pages 部署串成一条可重复的流程。
- 构建耗时不到一秒，产物约 40 KB（HTML + CSS + JS）。

## 复盘

- **先做数据，再做视觉。** 如果把页面当起点，很容易先堆组件，最后发现口径和边界都没想清楚。先让 JSON 可信，页面只是投影。
- **真实数据是测试用例。** 两个解析 bug 都不是构造样例能发现的：它们来自「标题没有空行」「连续划线没有空行」这种真实排版。
- **隐私检查要可执行。** 写在文档里的规则容易被忽略；把检查做成 `npm run check`，每次构建都能拦住。
- **公开范围是产品决策，不是技术默认值。** 第一版用白名单只放 24 条，后来改为全量公开：既然目标是展示判断链，就不该只给精选样本。白名单保留为可选项，但默认关闭，避免新增内容被静默排除。

## 下一步

- 增加按年份/主题的批注视图，而不是只按书筛选。
- 把「想法 → 主题」的轻量标注做成可选配置，方便回看长期关注的问题。
- 若想法数量继续增长，改为分页或多页静态生成。
- 增加构建前后的 diff 报告，方便发现同步异常（例如某本书突然少了章节）。
